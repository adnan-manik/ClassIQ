Model

What the system actually computes

Two models sit at the centre of ClassIQ: the Felder–Silverman profile that turns a survey into a student twin, and the four-factor score that turns a proposed section into a number. Both are implemented; the weights are configurable and not yet final.

FSLSM — the student twin

44-question ILS → four bipolar axes, scored −11…+11 (odd values only). Sign is the pole, magnitude is the strength.

ActiveReflective
SensingIntuitive
VisualVerbal
SequentialGlobal
+11+50−5−11
|s| ≤ 3Balanced
5 … 7Moderate
|s| ≥ 9Strong

Profiles are versioned — version + is_current. Retaking the survey writes a new row and keeps the old one, which is what makes the longitudinal stretch goal (S3) possible later without a migration.

Compatibility score — four weighted factors

Each factor scorer is a pure function returning 0–100. The aggregator is the only place weights are read; they live in scoring_configs.weights JSONB.

Style alignment0.40 Teacher interaction & pacing mapped to FSLSM affinities, against the class mean profile
Social cohesion0.25 NetworkX on the peer subgraph — connectivity and clustering, penalised by conflict density and isolation
Class balance0.20 Shannon entropy of the dominant-axis spread across the four axes
Participation mix0.15 L1 distance from an ideal mix of 15% low / 55% medium / 30% high
≥ 70High
50 – 69Medium
< 50Low

Output is a predicted outcome band, not a grade. ClassIQ is a decision-support tool — this number is never presented as a guarantee.

Simulation pipeline

In-process, synchronous, inside the request. POST /api/sections/{id}/simulate — the same score_roster path serves POST /api/scenarios/{id}/simulate.

Gather Teacher profile, current student profiles, aux profiles, peer edges repositories/
Score four factors Each a pure function returning score + evidence engines/scoring/*.py
Aggregate Weighted sum from scoring_configs scoring/aggregator.py
Persist Run, result, and one row per factor simulation_result_factors
Report Distribution, breakdown, outcome band, recommended teacher reports/ → print to PDF

Section states run draft → simulated → active → archived. A section cannot skip from draft to active — it must be simulated first, which forces an informed decision. Editing a simulated section drops it back to draft and orphans the previous run, which is kept for audit.
